# Data model

Source of truth: `packages/db/prisma/schema.prisma`. This document describes every table
in the Phase 1 schema and the conventions later phases must follow.

## Conventions

- **Primary keys**: UUID (`@db.Uuid`, generated by the application/Prisma)
- **Timestamps**: `timestamptz` in UTC; every mutable table has `created_at` and
  `updated_at`
- **Soft delete**: **not used in Phase 1.** Sessions, invitations and reset tokens expire;
  audit logs are append-only. Soft delete will only be introduced in later phases where
  recovery or audit value justifies it (e.g. invoices) — never as a blanket default.
- **Money (future invoicing/bookkeeping)**: stored as **integer minor units** (öre/cents)
  with an explicit currency code per document. Locked in now so Phases 4–5 don't drift.
- **Locale/currency**: default locale and currency live on `organizations`
  (`locale`, `currency`, default `SEK`); users carry their own `locale` for UI language.
- Table names are snake_case via `@@map`; enum `OrganizationRole` =
  OWNER, ADMIN, ACCOUNTANT, MANAGER, EMPLOYEE, READONLY.

## Tables

### users

Global identity, shared across organizations.

- `email` (unique), `password_hash` (Argon2id), `name`, `locale`
- `is_platform_admin` — instance-level operator flag (failed-jobs admin API); unrelated to
  any organization role

### organizations

Tenant root.

- `name`, `slug` (unique, auto-generated from name with collision suffix), `locale`,
  `currency`, `created_by_id`

### organization_members

User ↔ organization with a role.

- `organization_id`, `user_id`, `role` (enum)
- Unique `(organization_id, user_id)`; index on `user_id`
- Cascade-deletes with either parent

### sessions

Opaque server-side sessions (ADR-0002).

- `token_hash` (unique; SHA-256 of the raw cookie token — the raw token is never stored)
- `user_id`, `active_organization_id` (nullable — the session's current tenant context),
  `expires_at`, `last_used_at`, `ip`, `user_agent`
- Indexes on `user_id` and `expires_at` (cleanup)

### invitations

Invite lifecycle for memberships.

- `organization_id`, `email`, `role`, `token_hash` (unique), `expires_at` (7 days),
  `accepted_at`, `revoked_at`, `invited_by_id` (SetNull on user deletion)
- Pending = not accepted, not revoked, not expired
- Indexes on `organization_id` and `email`

### password_reset_tokens

- `user_id`, `token_hash` (unique), `expires_at`, `used_at` (single-use)

### audit_logs

Append-only audit trail.

- `organization_id` **nullable** — null for events before any org exists (registration,
  login, password reset)
- `actor_user_id` (SetNull so audit survives user deletion), `action` (stable string
  identifier), `entity_type`/`entity_id`, `metadata` JSONB, `ip`, `user_agent`
- Index `(organization_id, created_at DESC)` for the org-scoped audit page; index on
  `actor_user_id`

### outbox_messages

Transactional outbox (ADR-0005) — written in the same transaction as the domain change.

- `type` (doubles as AMQP routing key), `payload` JSONB, `occurred_at`,
  `published_at` (null = pending), `attempts`, `last_error`
- Index `(published_at, occurred_at)` for the relay poll

### processed_messages

Consumer idempotency ledger — at-least-once delivery made effectively once.

- Composite PK `(message_id, consumer)`, `processed_at`

### failed_jobs

Jobs that exhausted retries (dead-lettered), surfaced in the platform-admin API.

- `queue`, `message_type`, `payload` JSONB, `error`, `attempts`, `failed_at`,
  `retried_at` (set when re-enqueued through the outbox)
- Index `failed_at DESC`

## Tenancy rule for future tables

Every tenant-owned table added in later phases carries `organization_id` and is queried
only through the session-resolved active organization (see
[architecture.md](architecture.md#tenancy-model)). `users`, `outbox_messages`,
`processed_messages` and `failed_jobs` are intentionally global (identity and
infrastructure concerns).
